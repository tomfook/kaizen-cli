# planning-analysis

分析プロジェクトの計画立案・設計フェーズを支援するオーケストレーター。

## 計画立案フロー

| Phase | 内容 |
|-------|------|
| 0 | コンテキスト把握・ユーザーヒアリング |
| 1 | 問題定義・仮説設定 |
| 2 | データ要件定義 |
| 3 | 分析計画策定 |
| 4 | 検証計画策定 |

**重要**: Phase 0 → Phase 1の順序を守ること。データ構造やフィルタ方法を理解する前に仮説を設計すると、検証不可能な仮説や不適切な指標を選ぶリスクがある。

---

## Phase 0: コンテキスト把握・ユーザーヒアリング

仮説設計の**前に**、データの概観とユーザー要件を把握する。

### 0-1. データ構造の概観

1. 利用可能なデータソース（テーブル、ファイル等）を確認
2. 主要テーブルのカラム一覧を取得
3. 分析対象を特定するためのカラム候補を把握

**目的**: 仮説で使う指標やフィルタ条件が実際にデータ上で実現可能か確認する。

### 0-2. ディスカバリー質問

ユーザーに以下を確認し、Phase 1の仮説設計に必要な情報を収集する。

| # | 質問 | 目的 |
|---|------|------|
| Q1 | 分析対象をデータ上でどう特定するか？（フィルタ条件） | Phase 2のフィルタ条件設計 |
| Q2 | 「変化」の測定指標は何か？（金額/数量/率/複合） | Phase 1の仮説で使う指標 |
| Q3 | 比較軸は何か？（前年比/トレンド/セグメント間/複合） | Phase 1の仮説構造 |
| Q4 | 分析の粒度は？（全体のみ/カテゴリ別/個別） | Phase 1のサブ問題分解 |
| Q5 | 報告先・意思決定への利用方法は？ | 成功基準の粒度・レポート形式 |

#### 追加質問（効果測定の場合）

| # | 質問 | 目的 |
|---|------|------|
| Q6 | 施策期間と比較ベースライン期間は？ | 期間設定 |
| Q7 | 施策コストは把握できるか？ | ROI計算の可否 |
| Q8 | 対象群と非対象群の区分方法は？ | コントロール群の設計 |

#### 追加質問（トレンド分析の場合）

| # | 質問 | 目的 |
|---|------|------|
| Q6 | 「変化」をどう定義するか？（減少幅の閾値等） | 成功基準の設定 |
| Q7 | 外的要因を正規化するか？ | 正規化指標の要否 |
| Q8 | 比較対象はあるか？（他セグメント、他カテゴリ等） | 反証仮説の検証方法 |

### 0-3. Phase 0の完了条件

- [ ] データソースのカラム構造を把握した
- [ ] 分析対象のフィルタ方法が決まった
- [ ] 測定指標と比較軸が決まった
- [ ] 報告先・利用目的が明確になった

---

## Phase 1: 問題定義・仮説設定

### 必須要件

1. **主仮説を明文化**: 検証可能な形式で記述（曖昧な目標は不可）
2. **反証仮説を必ず設定**: 主仮説が「正しくない」場合に考えられる代替仮説
3. **確信度を付与**: 仮説に対する事前確信度を%で表現
4. **サブ問題に分解**: 複雑な問いは検証可能な小問題に分割

### 禁止事項

- 反証仮説なしでの計画策定開始
- 「○○を調べる」「○○を分析する」のような曖昧な目標設定
- 確信度なしでの仮説記載

---

## Phase 2: データ要件定義

### 必須チェック項目

| 項目 | 確認内容 |
|------|----------|
| データ品質 | 欠損値率、異常値、ゼロ値の意味を確認 |
| フィルタ条件 | 除外条件を明示的に定義 |
| 期間設定 | ベースライン/分析期間の定義 |
| 期間×比較軸の整合性 | YoY比較の場合、データが比較期間を含んでいるか |
| カラム名・指標の意味 | 使用カラムの業務上の意味を確認 |

> 参照: [PITFALLS.md § 1](../../../knowledge/analysis/PITFALLS.md#1-データ前処理の落とし穴)

### 出力物

以下を定義する:
- 使用テーブル・カラム
- フィルタ条件
- 計算指標の定義

## Phase 3: 分析計画策定

### 成功基準（必須・2段階）

**定量的基準を必ず設定**:
```
良い例: 「購入率が5%以上向上」「ROIが100%以上」
悪い例: 「効果があった」「改善した」
```

**2段階で設定する**:
- **暫定基準（Planning時）**: データを見る前に、業務知識や一般的な基準から仮設定
- **確定基準（EDA後）**: 実データの分布・変動幅を確認した上で、暫定基準を見直して確定

EDA後に暫定基準が妥当でないと判明した場合、根拠を明記して確定基準に修正する。

### リスク評価

評価すべきリスク:
- 季節性・外的要因の影響
- サンプルサイズ不足
- 因果関係と相関関係の混同
- 確証バイアス

> 参照: [PITFALLS.md § 2](../../../knowledge/analysis/PITFALLS.md#2-統計分析の注意点)

---

## Phase 4: 検証計画策定

### チェックポイント設定

| タイミング | 確認内容 |
|-----------|----------|
| データ取得後 | レコード数、期間、欠損率、ゼロ値割合 |
| 前処理後 | フィルタ適用結果、異常値対応 |
| 分析実行後 | 統計的妥当性、業務的妥当性 |
| 結論導出前 | 反証仮説の検討、不確実性の明示 |

---

## 批判的思考の強制適用

計画立案時に必ず適用する原則:

| 原則 | 計画時の適用 |
|------|-------------|
| 対立見解 | 反証仮説を必ず設定（Phase 1） |
| 不確実性分解 | 確信度を%で表現（Phase 1） |
| 自信バランス | 過剰な期待・悲観を排除（Phase 3） |
| サブ問題分割 | 複雑な問いは分解して検証計画（Phase 1, 4） |

---

## 禁止事項

1. **反証仮説なしでの計画完了**: 必ず「主仮説が正しくない場合」を検討
2. **曖昧な成功基準**: 「効果があった」ではなく定量的基準を設定
3. **データ品質チェックの省略**: Phase 2のチェック項目は必須
4. **批判的思考チェックの省略**: Phase 4のチェックポイントは必須

## カスタマイズのヒント

このファイルはサンプルです。自分のドメインに合わせて以下をカスタマイズしてください:

- ディスカバリー質問にドメイン固有の質問を追加（例: データソースのアクセス方法、業務固有のフィルタ条件）
- Phase 2のチェック項目にドメイン固有の確認事項を追加（例: 営業時間外データの除外、返品処理）
- 仮説テンプレートの追加（ドメインでよく使う仮説の型）
- 成功基準の業界標準値を追加（例: 「この業界ではROI 150%以上が成功」）
